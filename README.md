# 赛鸽血统环号登记站

运行：

```bash
npm start
```

访问 `http://localhost:3024`。支持档案、血统查询、转让、归巢成绩记录，以及录错足环后的**档案纠错（换号）**。

## 档案纠错规则

足环录错后不再新开档案，改为提交纠错单：

1. **提交**：填原环、新环、纠错原因、来源说明。新环已被别的鸽只当前占用时直接拒绝（`409 new_ring_occupied`），两边档案和履历均不动；原因或来源说明缺失同样拒绝。
2. **核对**：纠错单为待核对状态，人工确认后调用通过接口才真正换号；核对阶段再次发现新环被占用则拒绝换号。也可驳回，驳回不改任何数据。
3. **换号**：本鸽足环改为新环，所有父母/子代引用一并指向新环；旧环不删除，写入该鸽的 `ringHistory` 变更记录（含日期、原因、来源、纠错单号）。疫苗、转让、成绩原样保留并可继续追加。
4. **查询**：按原环或新环查询都定位到同一份血统；换号后旧环仍可录入疫苗/转让/成绩。

## 文件结构

纠错功能按业务拆成三层：

| 文件 | 职责 |
| --- | --- |
| `store.js` | 存储层：JSON 数据读写、档案/纠错单基础操作、换号落库 |
| `correction.js` | 判定层：占用校验、提交/核对通过/驳回规则、原环↔新环别名与血统解析 |
| `correctionApi.js` | 入口层：纠错相关 HTTP 路由（`/api/corrections`） |
| `page.js` | 页面：提交纠错、纠错单核对列表、原环/新环血统与变更记录查看 |
| `server.js` | 装配：页面托管、档案既有接口、调用纠错入口层 |

### 纠错接口

- `GET /api/corrections` 纠错单列表
- `POST /api/corrections` 提交纠错单：`{oldRing, newRing, reason, sourceNote}`
- `POST /api/corrections/:id/approve` 核对通过并换号：`{reviewer, reviewNote?}`
- `POST /api/corrections/:id/reject` 核对驳回：`{reviewer, reviewNote?}`
